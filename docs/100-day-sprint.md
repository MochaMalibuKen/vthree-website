## Content maintenance

`src/content/sprint.js` is the central public data file: schedule, timezone,
phases, typed project register, credentials, milestones, and weekly updates.
Types use JSDoc to match the existing JavaScript architecture. No dependencies
were added. The new page is explicitly marked as English within the bilingual
site; supplied English copy is preserved.

Keep all fields public-safe: hiding a field in a component does not prevent its
contents from appearing in the downloadable JavaScript. Internal project names
are deliberately replaced with public titles in the shipped register.

The initial register has three Active projects and nine Queued projects. All
outcomes are Targets. Entry dates record September 19, 2026 preparation of this
register; they are not completion dates. No reviewed milestones, verified
results, weekly updates, or publication claims have been fabricated.

Add milestone records with an ID, project ID, title, and ISO target date.
Only mark reviewed records with `evidenceReference`, `reviewedBy`, and a valid
`reviewedAt`. These are public review references, not confidential reviewer
information. The artifact may remain private; only add `evidenceUrl` for approved
public evidence. Overall progress is reviewed milestones divided by registered
milestones. With no records the requested tracking-start message is shown.
The next pending milestone is chosen by target date, falling back to the next
nonpaused, incomplete project's target when milestones are not registered yet.

Add the first weekly update only after verifying the implementation is live.
Updates support date, project ID, milestone completed, public evidence URL,
result, and next milestone. Set `sprintConfig.reportUrl` once the verified
report has been published. Until then the completed state reserves its location.

Both supplied badge images and the supplied completion certificate are used.
No external credential verification URLs were supplied, so none were invented.
The PMI credential uses the exact supplied name, not PMP certification.

## Countdown calculation

`getSprintState(now, timeZone)` takes an explicit instant. Intl.DateTimeFormat
extracts its calendar date in the configured timezone (`SPRINT_TIME_ZONE`,
America/Chicago). UTC ordinals of those calendar dates are subtracted, avoiding
23-hour and 25-hour DST days. September 23 is day 1; December 31 is day 100.
Active day numbers are clamped to 1–100. Days remaining exclude the current day.
Before launch it returns days until launch; January 1 in Chicago enters the
completed schedule state regardless of uncompleted project work.

The hook initially renders a stable schedule, then reads the browser clock after
mount, every 30 seconds, and on window focus. The current app uses createRoot
(client rendering), not hydration; the stable initial state also avoids future
SSR date mismatches.
